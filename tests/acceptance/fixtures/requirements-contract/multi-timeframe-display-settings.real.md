# 多周期图表显示设置 UX 需求分析

## 1. 文档信息

- 文档类型：需求分析 / UX 设计需求
- 目标模块：多周期图表显示设置
- 目标路径：`vnpy/chart/multi_timeframe_widget.py`、`vnpy/chart/multi_timeframe_settings_dialog.py`、`vnpy/trader/ui/widget.py`
- 创建日期：2026-06-23
- 当前结论：主图界面保留多周期状态摘要，细粒度显示和透明度设置迁移到紧凑设置面板。

## 2. 背景

当前多周期图表在同一张 1m 主时间轴图上叠加显示多个大周期 K 线，包括 `5m`、`15m`、`30m`、`45m`、`1H`、`4H`、`D`。这些周期的显示开关和透明度控制对分析有价值，但现有 UI 把多个周期的 slider、checkbox 和辅助按钮集中放在图表下方同一行，导致小屏幕下横向空间不足。

该问题不是简单的控件宽度问题，而是信息架构问题：主图下方区域应优先服务图表阅读和高频操作，而不是承载完整设置表单。多周期显示设置属于低频但重要的配置，应采用渐进披露方式集中管理。

## 3. 当前问题

### 3.1 图表下方控件过载

多周期图表底部同时承载以下内容：

- 多个周期的透明度 slider。
- 多个周期的显示 checkbox。
- 性能报告、离线任务等非显示设置按钮。
- 与图表本身交互相关的其他控件。

当窗口宽度较小时，控件会出现以下问题：

- 横向显示不完整。
- 控件被压缩后难以识别。
- slider 可操作区域过短，透明度调整不精确。
- 图表高度被无关设置区挤压。
- 用户无法快速判断当前到底显示了哪些周期。

### 3.2 显示设置与主图阅读目标冲突

用户进入多周期图表的核心目的通常是观察 1m 走势与少量关键大周期结构之间的关系。默认把 `15m`、`30m`、`45m` 也全部显示，会让画面信息密度过高，尤其在趋势边界、回撤结构、交易线和指标叠加时容易造成视觉干扰。

### 3.3 设置入口和默认行为不够统一

现有实现中默认显示状态可能分散在设置数据类、图表样式初始化和设置弹窗中。若只修改某一处默认值，会造成以下不一致：

- 新建图表显示一种状态。
- 打开设置弹窗显示另一种状态。
- 点击恢复默认又回到第三种状态。

因此默认显示策略必须作为产品级规则统一落地。

## 4. 目标

### 4.1 产品目标

为多周期图表提供一个小屏友好、低干扰、可快速理解的显示设置体验，使用户能在不牺牲图表可视区域的前提下管理所有叠加周期。

### 4.2 UX 目标

- 主界面只显示当前多周期状态摘要，不展示完整设置表单。
- 详细设置集中在一个紧凑、可滚动、按钮固定可见的设置面板中。
- 默认只显示核心周期，降低初始视觉噪音。
- 保留每个周期独立设置透明度的能力。
- 支持批量操作，减少重复点击。

### 4.3 工程目标

- 尽量复用现有 `MultiTimeframeSettings` 和 `_apply_settings` 数据流。
- 不改变多周期数据加载、聚合和绘制的核心逻辑。
- 不影响已存在的实时预览和取消恢复能力。
- 避免引入新的复杂窗口系统，优先使用现有 Qt 控件实现。

## 5. 非目标

本需求不包含以下内容：

- 不重新设计多周期 K 线绘制算法。
- 不改变 `15m`、`30m`、`45m` 的数据来源或聚合逻辑。
- 不改变 1m 主时间轴语义。
- 不新增复杂主题系统。
- 不引入 Web UI 或跨框架 UI。
- 不在本需求内解决图表拖拽、数据缺口、Futu 下载性能等非显示设置问题。

## 6. 用户与场景

### 6.1 高频观察场景

用户打开多周期图表后，主要关注 `5m`、`1H`、`4H` 与 1m 走势之间的结构关系。此时 UI 应尽可能少干扰图表阅读。

要求：

- 默认可直接开始观察。
- 不需要先关闭一堆中间周期。
- 当前显示周期一眼可见。

### 6.2 临时增强分析场景

用户需要临时查看 `15m`、`30m` 或 `45m`，用于确认中间周期结构。

要求：

- 能快速打开设置。
- 能单独启用某个周期。
- 关闭设置后主图立即反映变化。

### 6.3 透明度精调场景

用户发现某个周期过于抢眼或过淡，需要调整透明度。

要求：

- 能按周期单独调整透明度。
- 支持拖动快速调整。
- 支持精确输入百分比。
- 隐藏周期时保留透明度设置。

### 6.4 小屏使用场景

用户在 1366x768 或更小可用区域下使用图表。

要求：

- 主图底部不横向溢出。
- 设置面板可完整使用。
- `确定`、`取消`、`恢复默认` 等关键按钮始终可见。

## 7. 默认显示策略

默认显示策略应统一为：

| 周期 | 默认显示 | 默认透明度 | 说明 |
| --- | --- | --- | --- |
| 5m | 是 | 10% | 核心短周期结构 |
| 15m | 否 | 8% | 中间周期，按需启用 |
| 30m | 否 | 7% | 中间周期，按需启用 |
| 45m | 否 | 6% | 中间周期，按需启用 |
| 1H | 是 | 10% | 核心大周期结构 |
| 4H | 是 | 5% | 核心趋势结构 |
| D | 否 | 5% | 日线结构，默认避免遮挡 |

`1m` 是主时间轴，不属于叠加周期，不在多周期显示设置中提供显示开关。

## 8. 信息架构

### 8.1 主图区域

主图区域只保留多周期状态摘要和设置入口。

推荐显示：

```text
多周期: 5m 1H 4H    隐藏: 15m 30m 45m D    设置
```

小屏显示：

```text
多周期: 5m 1H 4H    设置
```

小屏下隐藏周期摘要进入 tooltip：

```text
隐藏周期: 15m, 30m, 45m, D
```

### 8.2 设置面板

设置面板承载完整周期设置。它可以是现有 `QDialog` 的重构版本，也可以后续升级为非模态右侧面板。第一阶段推荐继续使用 `QDialog`，降低回归风险。

设置面板主体采用紧凑表格，而不是多个垂直 `GroupBox`。

推荐结构：

```text
周期   显示   透明度                         数值   操作

45m    □     [━●━━━━━━━━]                    6%    默认
1H     ✓     [━━━━━━●━━━━]                  10%    默认
4H     ✓     [━━●━━━━━━━]                    5%    默认
D      □     [━━●━━━━━━━]                    5%    默认
```

## 9. 功能需求

### FR-1 主图显示状态摘要

系统应在多周期图表中显示当前启用的叠加周期摘要。

验收：

- 默认摘要显示 `5m 1H 4H`。
- 用户启用 `15m` 后摘要包含 `15m`。
- 用户隐藏所有周期后摘要显示 `无叠加周期` 或等价提示。

### FR-2 详细设置入口

系统应提供一个明确的多周期设置入口。

验收：

- 入口在多周期模式下可见。
- 单周期模式下不显示或禁用该入口。
- 点击入口打开完整设置面板。

### FR-3 周期显示开关

系统应允许用户分别控制 `5m`、`15m`、`30m`、`45m`、`1H`、`4H`、`D` 的显示状态。

验收：

- 勾选后该周期在图表中显示。
- 取消勾选后该周期从图表中隐藏。
- 隐藏不删除数据，不触发重新下载。

### FR-4 周期透明度设置

系统应允许用户分别控制每个叠加周期的透明度。

验收：

- 每个周期有独立 slider。
- 每个周期有百分比数值显示。
- 推荐提供 `QSpinBox` 精确输入。
- 调整后图表实时预览。

### FR-5 隐藏周期保留透明度

系统应在隐藏周期时保留其透明度设置。

验收：

- 用户将 `15m` 透明度设为 `12%`。
- 用户隐藏 `15m`。
- 用户重新显示 `15m`。
- `15m` 透明度仍为 `12%`。

### FR-6 单周期默认重置

系统应允许用户只重置某一周期的透明度。

验收：

- 点击某行 `默认` 后，只重置该周期透明度。
- 其他周期显示状态和透明度不变。

### FR-7 批量操作

系统应提供批量操作以降低重复点击。

必须提供：

- `核心周期`：只显示 `5m`、`1H`、`4H`。
- `全部显示`：显示所有叠加周期。
- `全部隐藏`：隐藏所有叠加周期。
- `恢复默认`：恢复产品默认显示和透明度。

建议提供：

- `统一透明度 5%`
- `统一透明度 10%`
- `自定义统一透明度`

### FR-8 取消恢复

系统应保持现有取消恢复语义。

验收：

- 打开设置面板后修改显示和透明度。
- 图表可以实时预览。
- 点击取消后恢复打开面板前的状态。
- 点击确定后保留修改。

### FR-9 小屏自适应

系统应在小屏幕下保持可用。

验收：

- 1366x768 分辨率下主图底部不横向溢出。
- 设置面板最大高度不超过屏幕可用高度的约 70%。
- 表格区域可滚动。
- 底部按钮固定可见。

## 10. 非功能需求

### 10.1 可读性

- 主图不应显示完整设置表单。
- 设置面板行高应紧凑但不拥挤。
- 周期名称使用统一短标签：`5m`、`15m`、`30m`、`45m`、`1H`、`4H`、`D`。

### 10.2 性能

- 打开设置面板不应触发数据重新加载。
- 切换显示状态只调用显示层更新。
- 调整透明度只更新绘制样式，不触发聚合或下载。

### 10.3 可维护性

- 默认值应集中定义或通过单一辅助函数生成，避免多处硬编码。
- 设置数据结构应继续使用 `MultiTimeframeSettings` 或等价对象。
- UI 控件到设置对象的映射应表驱动，避免为每个周期复制大量重复代码。

### 10.4 兼容性

- 不改变已有 `_apply_settings` 对外语义。
- 不破坏 `show_settings_dialog` 的返回行为。
- 不影响单周期图表。
- 不影响数据管理器、Futu 下载、回放、回测等非图表显示模块。

## 11. 交互细节

### 11.1 表格行状态

当周期显示关闭时：

- checkbox 取消选中。
- 行内 slider 和数值仍可见。
- 行视觉上可轻微置灰。
- 不清空透明度设置。

理由：用户可能先配置透明度，再决定是否显示；隐藏状态不代表配置失效。

### 11.2 实时预览

设置面板内操作应支持实时预览。

规则：

- checkbox 改变后立即更新图表显示状态。
- slider 改变后立即更新透明度。
- spinbox 改变后与 slider 同步。
- 点击取消时回滚到打开面板前快照。

### 11.3 批量按钮行为

`核心周期`：

- `5m`、`1H`、`4H` 显示。
- `15m`、`30m`、`45m`、`D` 隐藏。
- 不强制重置透明度，除非按钮文案为 `恢复默认`。

`恢复默认`：

- 恢复显示状态。
- 恢复默认透明度。

`全部隐藏`：

- 所有叠加周期隐藏。
- 主图摘要显示 `无叠加周期`。
- 1m 主时间轴仍正常显示。

## 12. 实现建议

### 12.1 第一阶段：低风险重构

第一阶段目标是解决拥挤和默认显示问题，不做窗口系统升级。

建议改动：

- 将 `15m`、`30m`、`45m` 默认显示改为 `False`。
- 保持 `D` 默认隐藏。
- 移除或隐藏 `MultiTimeframeWidget` 底部完整 slider/checkbox 控制行。
- 增加紧凑状态摘要。
- 将设置弹窗从 `GroupBox` 堆叠改为表格式布局。

### 12.2 第二阶段：体验增强

如果第一阶段稳定，再考虑：

- 把设置弹窗升级为非模态右侧设置面板。
- 增加周期 chip 的快速开关。
- 增加最近使用组合。
- 增加设置持久化到用户配置。

第二阶段不应阻塞第一阶段落地。

## 13. 测试建议

### 13.1 单元测试

覆盖：

- 默认 `MultiTimeframeSettings` 中 `visible_15m=False`、`visible_30m=False`、`visible_45m=False`。
- `恢复默认` 后显示状态符合默认策略。
- `取消` 后状态回滚。

### 13.2 UI 行为测试

覆盖：

- 打开多周期图表后默认只显示 `5m/1H/4H`。
- 启用 `15m` 后图表 item 可见。
- 隐藏 `15m` 后图表 item 不可见。
- 调整 `30m` 透明度后样式值同步。

### 13.3 小屏回归测试

覆盖：

- 1366x768 下主图底部无横向溢出。
- 设置面板按钮区域可见。
- 表格区域滚动正常。

## 14. 验收标准

本需求完成后应满足：

- 默认进入多周期图表时，`15m`、`30m`、`45m` 不显示。
- 主图下方不再展示 7 组完整透明度 slider 和 checkbox。
- 主图可清晰看到当前启用周期摘要。
- 设置面板可完整管理 7 个叠加周期。
- 每个周期仍可独立设置透明度。
- 取消设置可恢复原状态。
- 恢复默认可回到 `5m/1H/4H` 显示、`15m/30m/45m/D` 隐藏。
- 小屏幕下设置入口和关键按钮可用。

## 15. 风险与约束

### 15.1 回归风险

如果直接删除底部控件，可能影响现有代码中依赖 `_slider_*` 或 `_checkbox_*` 成员的逻辑。因此第一阶段应谨慎处理：

- 可以先隐藏底部控件而不是删除成员。
- 或保留成员但迁移到设置面板映射中。
- `_apply_settings` 中同步控件状态的逻辑需要保持安全空判断。

### 15.2 默认值分散风险

默认值必须统一，否则会出现初始化、弹窗、恢复默认三者不一致。建议新增单一默认配置生成函数，例如：

```text
create_default_multi_timeframe_settings()
```

所有初始化和恢复默认都从该函数读取。

### 15.3 设置持久化边界

若现有系统只持久化透明度，不持久化显示状态，需要明确第一阶段是否增加显示状态持久化。推荐第一阶段至少保证运行期一致；持久化可作为独立增强项处理。

## 16. 推荐落地顺序

1. 增加统一默认设置函数。
2. 修改 `15m/30m/45m` 默认显示为 `False`。
3. 改造设置弹窗为紧凑表格布局。
4. 增加主图状态摘要。
5. 隐藏或移除底部完整设置控件。
6. 补默认值、恢复默认、取消回滚、小屏显示测试。
7. 手工检查 1366x768 下的显示效果。

## 17. 最终方案摘要

多周期显示设置的最优 UX 不是压缩所有控件，而是重新划分主界面和设置界面的职责：

- 主界面负责看图，只展示启用周期摘要和设置入口。
- 设置面板负责配置，用紧凑表格管理显示和透明度。
- 默认策略聚焦核心周期，避免中间周期默认干扰视图。
- 小屏优先保证图表可读性和关键按钮可访问。
